# Part1 : Checking your understanding

## Ex1
Months are spent creating a rigid and absolute specification for the project.  
It is therefor not easy to change direction or add features / change features inside the Building phase.  
If changes are necessary you are forced to return to the Planning phase and redo the specification.  
So every time you need to make a change / something didn't work / didn't pass testing. You go back one of more steps.

## Ex2
- Individuals and interactions over processes and tools

How to implement the story is up to the individual not delegated by a project leader.  

- Working software over comprehensive documentation

You create many MVP itterations slowly growing your product into full-featured rather than one gigantic v1.0 release  
in accordance with the rigid specification.  

- Customer collaboration over contract negotiation

You work closely with the product owner throughout the project having weekly meetings presenting the latest MVP.  
They can then decide if the result is what they had in mind or make changes going forward. Itterative delivery process.  

- Responding to change over following a plan

Continueous feedback from product owner over feature set / design. Feedback from team over tooling / implementation.  
The next sprint is decided on changes needed going forward based in feedback a week old not months.
